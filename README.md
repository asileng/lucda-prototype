# LuCDA

把可疑的话发进来 —— 文字、语音、图片都行。它回一段带色块的文本，点开任意色块能看到**为什么**，最后告诉你**该怎么说**。

**在线原型**：[asileng.github.io/lucda-prototype](https://asileng.github.io/lucda-prototype/)

> 公开站默认走**离线演示模式**：点右上角「演示样例」，7 条结果都是真实调用出来的，本地存着，**断网也能看**。
> 为什么公开站不联网、以及怎么接上真模型，见下面「联网（可选）」。

## 它能做什么，不能做什么

| 做 | 不做 |
| --- | --- |
| 识别**话语在做什么**：用了哪些说服杠杆、针对谁、想让你做什么 | 判断**信息真假**：产品是否有效、机构是否真实、批号是否合法 |
| 给出**可溯源**的依据（理论 → 文献 → 语料例证） | 给出法律意见或取证建议 |
| 生成**匹配对象**的说服话术 | 代替用户与对方交涉 |
| 判风险等级并转交官方出口（12315 / 96110） | 承担核查职责 |

**能力边界**：LuCDA 只分析话术怎么骗人，不判断产品真假。

判据是「只说看见了什么 / 没看见什么」：

- 「包装上**没有找到**批准文号」—— 可以
- 「批准文号**是伪造的**」—— 不可以（那需要外部数据库比对）

## 目录

| 路径 | 作用 |
| --- | --- |
| `GOAL.md` | 目标、边界、信息模型、CFG 唯一真源 |
| `计划1_执行指令.md` | 执行依据：设计原则、说服框架、禁忌库、schema、技术规范、验收标准 |
| `HANDOFF_计划1执行.md` | 环境、铁律、报告格式 |
| `schema/` | 机读契约：`annotation.schema.json`（三模态同构）、六杠杆判据、禁忌库规格、场景矩阵、提示词契约 |
| `data/` | 运行时数据：禁忌规则、依据索引、离线演示样例 |
| `worker/` | 统一出口（Cloudflare Workers）+ 本机答辩代理 + 生成脚本 |
| `web/` | 前端源码（唯一界面，纯静态零构建） |
| `docs/` | **发布产物**（由 `web/` 构建而来，GitHub Pages 从这里发布） |
| `tools/` | 构建、测试、出图脚本 |
| `assets/` | 配图：CFG、原型截图、三方对标 |

`web/` 是源码，`docs/` 是产物。改前端要改 `web/`，然后跑一次构建。

## 本地跑

```bash
npm run build      # 把 web/ 构建成 docs/
npm run serve      # 起本机静态服务，打开 http://127.0.0.1:8080/docs/
```

打开页面后点右上角「演示样例」—— 那是本地存着的完整结果，**断网也能用**。

> 直接双击 html 文件打开会看不到结果：`file://` 取不到 `data/*.json`。要用静态服务器。

## 联网（可选）

公开站默认走**离线演示模式**。原因是 GitHub Pages 是纯静态站，任何写进前端的 key 都能被人下载走。

要联网分析，先部署 `worker/`：

```bash
cd worker
npx wrangler secret put DEEPSEEK_API_KEY   # key 只存在 Worker 的环境变量里
npx wrangler deploy
```

拿到地址后填进 `web/config.js`：

```js
window.LUCDA_CONFIG = { API_BASE: "https://你的-worker.workers.dev" };
```

然后重新 `npm run build`。答辩现场想本机真跑，也可以填 `http://127.0.0.1:8787` 并 `npm run dev:api`。

## 部署

**Worker**：见上一节。

**GitHub Pages**：本 branch 的 `/docs` 目录。改了前端之后：

```bash
npm run build
git add -A && git commit -m "更新前端并重建发布产物"
git push
```

Pages 会在几十秒内重新发布。

## 语音这一路

界面保留了「按住说话」入口，但**真实语音识别还没做**，放到后面开发。

页面不会伪造转写结果：点它会如实说明，并引导用「📋 粘贴文字」。演示样例里的语音条目用的是**人工转写**的时间轴文本，界面上也标明了这一点。

## 依据从哪来

`data/rag_index.json` 是静态索引，浏览器本地检索（原型阶段不上向量库）。每条依据分三层：

1. **理论** —— 触发了哪个概念（预设 / 信息确定性 / 情绪引导 / 加工路径 / 六杠杆）
2. **文献** —— 哪一篇支持（标题 + 作者 + 年份），带 `可核实性` 字段
3. **语料例证** —— 同类真实片段

索引里标「待核实」的条目尚未逐条核对，不当作已确认的出处引用。语料层当前是**自建样例**，语料加工完成后替换。
