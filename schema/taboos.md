# 禁忌库（执行指令 §5）

> **这是什么**：一个运行时组件，不是给人读的文档。任何一段准备送达用户的输出，
> 送出前必须过一遍 `web/taboos.js` 的 `scan()`，命中的进 `策略.禁忌` 栏（执行指令 §4.1 第 ⑥ 栏、§6.6）。
> **对应规格**：执行指令 §5.2（四种成因）、§5.3（禁忌表）、§5.4（通用禁用语）、§5.5（执行方式）、§11 验收 10。
> **边界**：只判「这句话该不该说出去」。不判断产品真假、不核验资质（执行指令 §1.3）。
> 本文件里凡是超出规格原文的条目，一律标了 `自建`，待语料核实。

---

## 0. 三个文件的关系

| 文件 | 性质 | 谁读它 |
| --- | --- | --- |
| `schema/taboos.md` | 本文件。规格与口径，人读 | 评审、实现者 |
| `data/taboos.json` | 规则数据。词表 / 组合禁忌 / 句式规则 / 改写建议 | 前端启动时 `fetch` 后 `loadRules()` 注入 |
| `web/taboos.js` | 扫描器。纯 JS、零依赖、零 CDN，离线可用 | 浏览器与 Node 同一个对象 |
| `tools/taboo_test.mjs` | 验收。10 条预置用例 + 阴性对照 | 收工自检 |

`web/taboos.js` 里内置了一份 `data/taboos.json` 的**兜底副本**：`fetch` 失败时离线仍可用（执行指令 §8.6 离线演示模式）。
外部注入时按节覆盖兜底副本。**两份内容必须一致**，`tools/taboo_test.mjs` 第 [0] 项会比对，
不一致即断言失败——改完 `data/taboos.json` 要按同一份内容重新生成兜底副本。

### 0.1 API

```js
LuCDA.taboo.scan(text, { 用户, 对抗者 })
// → { 通过: boolean,
//     命中: [ { 片段, 位置, 规则, 类别, 成因, 优先级, 处理, 改写, 改写说明, 来源, 命中词 } ],
//     扫描: { 版本, 规则来源, 用户, 对抗者, 上下文完整, 评估到的规则数, 未评估规则, 未覆盖规则 } }

LuCDA.taboo.rewrite(text, 命中)        // → 改后的文本；有任一条命中没有「替换」型改写建议时返回 null
LuCDA.taboo.enforce(text, { 用户, 对抗者 })  // → { 状态, 文本, 命中, 记录, 扫描 }，走完 §5.5 全程
LuCDA.taboo.loadRules(rules)           // 注入 data/taboos.json
LuCDA.taboo.getRules() / resetRules()
```

`scan` 的 `通过: true` 只表示「没命中禁忌」，**不表示这段输出可以发**——绿色仍要走 §9.4 的正常说法对照。

### 0.2 命中条目的字段

| 字段 | 含义 |
| --- | --- |
| `片段` | 命中的原文片段（原文下标，含字间空白容错） |
| `位置` | `[起点, 终点]`，字符下标 |
| `规则` | 规则编号 + 说明，如 `T-01 老人 × 推销员`、`S-06 追责式重提旧话…` |
| `类别` | `组合禁忌` / `句式规则` / `通用禁用语·权威类｜绝对类｜论据类｜姿态类` |
| `成因` | 执行指令 §5.3 的成因原话，或 §5.4 的三类硬约束标签 |
| `处理` | `替换` / `删句` / `删词`，见 §5.2 |
| `改写` | `处理 = 替换` 时的替换文本；其余为空 |
| `改写说明` | 给生成侧看的处理意见（不是可直接替换的文本） |
| `来源` | 追到规格哪一处，≤1 次点击 |

## 1. 四种成因（执行指令 §5.2）

| 成因 | 机制（规格原话） | 典型（规格原话） | 可判定的匹配面 |
| --- | --- | --- | --- |
| **伤面子** | 触发自我防御，对方为维护自我形象而加倍坚持 | 「你被骗了」 | 对人下身份/能力结论：`你被骗了` / `你别傻了` / `你是不是老糊涂了` / `你怎么这么糊涂` |
| **触发逆反** | 变成权力对抗，立场让位于关系 | 「我早就跟你说过」 | 追责式重提旧话：`早就跟你说过` / `说过多少回` / `你怎么不听` / `你就是记不住` |
| **堵死退路** | 对方为保全面子只能更强硬 | 当面对推销员喊「骗子」 | 单方面贴标签 + 威胁：`你们就是骗子` / `我报警抓你`（S-09） |

命中条目里这三类直接标 `权威符号` / `绝对化表述` / `把 AI 判断当论据`，不硬塞进四类。

### 2.2 上下文缺失时

`用户` 或 `对抗者` 为空时：`T-12`（任何人 × 任何人）仍评估，其余按格生效的规则**跳过不评估**，
并在 `扫描.未评估规则` 里逐条列出，`扫描.上下文完整` 记 `false`。**不静默当通过。**

## 3. 通用禁用语（执行指令 §5.4）

| 类别 | 词表 | 说明 |
| --- | --- | --- |
| **权威类** | 最强 / 最准 / 最权威 / 国家级 / 独家 / 权威 AI / 独家算法 | §5.4 原文七条，一字不改 |
| **绝对类** | 100% / 100％（自建）/ 百分之百（自建）/ 绝对 / 保证 / 一定 / 肯定 | §5.4 原文五条；另两条是同义/全角写法 |
| **论据类** | *（词表为空）* | §5.4 原文只给了描述「把 AI 判断本身当论据（须改写为『依据是……』）」。全部由句式规则 **S-14** 承担 |
| **姿态类** | 你必须 / 你不许 / 我这是为你好 / 早就跟你说过 | §5.4 原文四条 |

### 3.1 匹配口径（可被代码判定）

1. **字面匹配，字间允许空白**：`你必须` 同时命中「你必须」和「你 必须」；`100%` 同时命中「100%」和「1 0 0 %」。
   位置以原文下标为准。
2. **含拉丁字母的条目大小写不敏感**（`权威 AI` 命中「权威 ai」）。
3. **排除前缀**（挡住同形异义）：

   | 条目 | 排除前缀 | 排除后缀 | 理由 |
   | --- | --- | --- | --- |
   | 一定 | 不 没 未 无 | 程度 | 「不一定」「一定程度」不是绝对化表述 |
   | 保证 | 不 没 未 无 | 金 期 人 书 | 「不保证」「保证金」「保证期」不算 |
   | 肯定 | 不 没 未 无 | — | 「不肯定」不算 |
   | 绝对 | 不 没 非 | — | 「不绝对」不算 |

4. **论据类只挡「把 AI 判断当论据」，不挡提到 AI**。命中条件：出现 `AI / 人工智能 / 大模型 / 模型 / 算法 / 系统 / 机器`
   ＋ 一个判断动词（说 / 认为 / 判断 / 判定 / 显示 / 给出 / 结论 / 结果 / 看法 / 意见 / 分析）。
   同一句里已经出现 `依据是 / 理论 / 文献 / 语料 / 例证 / 可溯源` 的，不算命中。
   **按这条口径，执行指令 §7.5 要求的免责声明「分析基于 AI，供参考，不构成法律意见」不会被误报**（测试 A-05 断言）。
5. **权威类 / 绝对类不生成替换文本，一律走降级（删段）**。理由：删掉「100%」解决不了那句绝对承诺，
   凭空给一句替代说法等于生造新断言——安全侧是让这段话不出去。

## 4. 句式规则（改写型禁忌）

**词表匹配不到的同义变体靠这一节。** 每条模式是可编译的正则；`生效条件` 为空表示不限上下文。

| --- | --- | --- | --- | --- | --- | --- |
| S-01 | `(你\|您)(必须\|必须得\|必须要\|务必\|一定要\|一定得)` | 第二人称 + 强制词 = 下命令，否掉的是对方的能力 | 剥夺自主 | 不限 | 替换 → `你可以` | T-12 |

S-14 完整模式（与 `data/taboos.json` 逐字一致，两个分支取或）：

```text
(根据|按照|依据|凭|依)\s*([Aa][Ii]|人工智能|大模型|模型|算法|系统|机器)[^，。！？\n]{0,6}(的)?(说|判断|判定|结论|结果|看法|意见|分析|给出)|([Aa][Ii]|人工智能|大模型|模型|算法|系统|机器)\s*(说|认为|判断|判定|显示|给出|结论|结果|看法|意见)
```

> 模式的逐字真源是 `data/taboos.json` 的 `句式规则.行[].模式`（以及由它生成的 `web/taboos.js` 兜底副本）。

**来源标注**：S-01 / S-02 的模式从 §5.4 姿态类的两条字面串扩出；S-06 / S-07 / S-08 / S-09 / S-11 / S-13 从 §5.3

## 5. 执行方式（执行指令 §5.5）

### 5.1 流程图

```text
       生成输出
          ↓
   禁忌扫描 scan(text, {用户, 对抗者})
          ↓
   ① 命中 §5.3 对应格？ ② 命中 §5.4 词表？ ③ 命中句式规则？
          ↓
        ┌── 未命中 ──────────────────────────→ 放行
        ↓
   命中 → 按 处理 动作重写该段 → 再扫 scan()
        ↓
        ┌── 未命中 ──────────────────────────→ 重写后放行（记录改了什么）
        ↓
   仍有命中 → 降级：删掉命中所在整段，产出不含该段的安全输出 → 再扫
        ↓
        ┌── 未命中 ──────────────────────────→ 降级（记录删了哪几句）
        ↓
   仍命中 → 降级为空（文本为空，不许送出去）/ 降级失败（记录，交人工）
```

**硬约束**：扫描在**送达用户之前**执行，不是写作时执行。运行时的入口是 `enforce()`，它一次走完全程。

### 5.2 三种处理动作

| 处理 | 做什么 | 算不算重写成功 |
| --- | --- | --- |
| `替换` | 用 `改写` 字段的文本换掉命中片段，功能不变、说法变 | 算。`rewrite()` 能吃下去 |
| `删句` | 删掉命中所在整句（以 `。！？` 与换行为界） | 不算。记 `降级` |
| `删词` | 只删掉命中的词 | 不算。记 `降级` |
| 默认 | 条目没声明 `处理` 时记 `删句`（安全侧） | 不算 |

`rewrite(text, 命中)` 的契约：**只要有任意一条命中不是 `替换` 型，就返回 `null`**——由调用方走降级。
这与 §5.5 的分支一致：能重写就重写，不能重写就降级。

### 5.3 状态取值

| 状态 | 含义 | 能不能送出去 |
| --- | --- | --- |
| `放行` | 一次都没命中 | 能 |
| `重写后放行` | 全部命中都被 `替换` 型改写吸收，再扫通过 | 能 |
| `降级` | 有段被删掉，剩下的文本再扫通过 | 能（文本已不含该段） |
| `降级为空` | 删完什么都不剩 | **不能**，要重新生成或人工处理 |
| `降级失败` | 删完仍命中（位置对不上等） | **不能**，记录后人工处理 |

### 5.4 记录格式

`enforce()` 返回的 `记录` 是数组，每条形如：

```json
{ "动作": "重写", "规则": "组合禁忌：你必须", "片段": "你必须", "换成": "你可以" }
{ "动作": "降级", "规则": "通用禁用语·绝对类：保证", "片段": "保证",
  "处理": "删句", "删掉的整句": "我给你保证，这东西绝对没问题。" }
{ "动作": "跳过", "规则": "通用禁用语·绝对类：绝对", "原因": "该段已被前面一条规则整句删除" }
```

降级记录必须留下，不能只删不记（§5.5「并记录」）。

### 5.5 两层防线

`scan()` 是**第二层**（生成后校验）。第一层在生成侧：写提示词时就把 §5.3 / §5.4 的约束写给模型
（见 `schema/prompt_contract.md`），扫描器只兜住漏网的。只靠扫描器会漏（见第 7 节）。

## 7. 已知覆盖缺口（写进库里，不藏）

| # | 缺口 | 影响 | 应对 |
| --- | --- | --- | --- |
| 1 | **T-10 点名羞辱当事人只能部分覆盖**。正则认得「大家看 / 某某 / 这个人 + 上当」这一族句式，认不出真实姓名、楼栋号、称谓 + 具体行为 | 社区工作者档可能漏判 | 生成侧加一条硬规则：社区工作者档输出不得出现可指认到具体当事人的信息（执行指令 §4.5、§12） |
| 2 | **元语言引用不区分**。输出里原样引用禁忌说法（比如「不能说『你被骗了』」）也会被判命中 | 可能拦下要人再核 | 取舍是安全侧：宁可让人看一眼，不放过真命中 |
| 3 | **同形异义只挡了列出的那几组**（不一定 / 保证金 / 不肯定 / 不绝对 / 一定程度） | 更细的义项判别做不到 | 字面匹配的能力边界（执行指令 §10.4「禁忌扫描漏判」），接受并记下 |
| 4 | **字间空白容错有上限**。`1 0 0 %` 能命中；拆到跨句、加标点的写法命中不了 | 绕法可能漏 | 生成侧不产生这类文本；漏判由第 2 层之外的人工复核兜 |

**这四条都不算「已解决」，算「已声明」。** 拿它当 100% 覆盖会出错。
