# worker/ — LuCDA 统一出口

Cloudflare Worker 出口（线上）与本机答辩代理（离线）共用同一份实现。
**key 只在服务端**，前端（GitHub Pages 是纯静态站）永远拿不到 key（执行指令 §10.1、§10.2、铁律 12）。

## 文件

| 文件 | 作用 |
| --- | --- |
| `worker.js` | 出口本体：system prompt 内联、调上游、契约校验、修复重试、降级、限流、CORS、路由。**唯一实现** |
| `dev-server.mjs` | 本机答辩用代理：node 内置 http，导入 `worker.js` 的路由表，路由与响应格式完全一致 |
| `validator.js` | 契约校验器（JSON Schema 子集，零依赖）。Workers 装不了依赖，所以自己写一份；测试也用它 |
| `schema.js` | `schema/annotation.schema.json` 的运行时副本，**由 `gen_schema.mjs` 生成，不要手改** |
| `rag_index.js` | 依据清单的运行时副本，**由 `gen_index.mjs` 生成，不要手改** |
| `gen_prompt.mjs` | 把 `schema/prompt_contract.md` §1 的 system prompt 逐字注入 `worker.js` |
| `gen_schema.mjs` | 由契约生成 `worker/schema.js` |
| `gen_index.mjs` | 由 `data/rag_index.json` 生成 `worker/rag_index.js`（只保留「已核实」文献） |
| `make_demo_samples.mjs` | 真实调用生成 `data/demo_samples.json`（离线演示样例） |
| `make_test_image.py` | 用 PIL 造一张虚构保健品包装图，供图片模态联调 |
| `test_image.png` | 上面那张图（1000×1400，114 KB） |
| `wrangler.toml` | 部署配置 |

生成物与真源的关系：改了真源就跑一遍对应脚本。

```bash
node worker/gen_prompt.mjs   # schema/prompt_contract.md → worker.js 里的 SYSTEM_PROMPT
node worker/gen_schema.mjs   # schema/annotation.schema.json → worker/schema.js
node worker/gen_index.mjs    # data/rag_index.json → worker/rag_index.js
```

## 路由

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/analyze` | 分析一次输入，返回 §6.6 JSON |
| `GET` | `/health` | 自检：模型名、限流口径、密钥是否读到（**只报有 / 没有，不返回值**） |
| `OPTIONS` | 任意 | CORS 预检，204 |

### 请求

```json
{ "模态": "text",  "内容": "小李说这个胶囊能治糖尿病，我很信任他" }
{ "模态": "image", "内容": "data:image/png;base64,……" }
{ "模态": "audio", "内容": "[0.0-4.2] 阿姨，这个我先给您留三盒……", "转写来源": "人工转写" }
```

| 模态 | 内容是什么 | 上游模型 | 上限 |
| --- | --- | --- | --- |
| `text` | 文字 | `deepseek-v4-pro` | 8000 字（执行指令 §7.1） |
| `image` | 一张图的 data URL | `deepseek-flash` | 解码后 ≤ 4.5 MB，1 张 / 次（§7.3） |
| `audio` | **已经存在的转写文本**（带时间轴） | `deepseek-v4-pro` | 8000 字 |

**语音这一条要说明白**：本出口**不做语音识别**。不传 `转写来源` 的 `audio` 请求直接返回 `501 未实现`，
**不会返回任何编造的转写结果**（用户 2026-10-01 决定：真实 ASR 放到未来开发）。
带上 `转写来源`（如 `"人工转写"`）时，出口只做一件事：按**语音模态**去标注这段**别人给的**转写文本——
`meta.证据单位` 仍是 `时间轴`，语音独占观察（同一承诺重复次数等）照常填（§7.2、§6.4）。
出口从头到尾不生成转写，只接受已经存在的转写文本。

### 响应

| 状态码 | 内容 |
| --- | --- |
| `200` | §6.6 JSON 本体（不是包一层信封），八个顶层键，字段与 `schema/annotation.schema.json` 一致 |
| `400` | 请求不合格式（模态非法、内容为空、文字超长、image 不是 data URL） |
| `413` | 请求体或图片超上限 |
| `429` | 触发限流 |
| `501` | `audio` 且没有声明 `转写来源` → 未实现 |
| `502` | 上游报错 / 返回不合契约（含两次都不合契约） |
| `503` | 服务端没读到 `DEEPSEEK_API_KEY` |
| `504` | 上游超时 |

`502` / `503` / `504` 返回的是**降级对象**，形状固定：

```json
{
  "状态": "降级",
  "错误": { "标记": "DEGRADED_INVALID_OUTPUT", "说明": "…", "校验错误": ["…"], "原始返回片段": "…" },
  "meta": { "模态": "text", "证据单位": "原文" },
  "判定": null,
  "策略": null,
  "溯源": [],
  "提示": "这次没有通过契约校验，所以不给判定。可以再发一次，或改用离线演示样例。"
}
```

**关键点：降级时 `判定` 是 `null`。** 校验不过就承认没分析出来，绝不拿一个「绿」冒充结论
（执行指令 §9.4、§2 铁律 13）。前端看到非 200 或 `状态 !== "成功"`，切离线演示样例。

### 送出前的四步（顺序不可颠倒，同 `schema/prompt_contract.md` §0）

```text
模型返回 → ① JSON 解析 → ② schema 校验 → ③ 策略形态检查（§4.2 / §9.1 / §9.2）→ ④ 高风险补齐官方出口（§11 验收 7）
                        └ ① / ② 失败：把错误回灌给模型，重试一次；再失败 → 降级对象
                        └ ③ 不合：回灌「只改 策略 这一栏」一次；仍不合不降级，只记在 日志.形态检查
                        └ ④ 是确定性护栏，不靠模型（补齐只写 12315 / 96110）
（呈现前那一遍禁忌扫描在前端侧：web/taboos.js）
```

**第 ③ 步为什么要有**：schema 只管「键与取值合不合法」，管不了「这个用户档该出哪种形态」。
实测模型会给 `用户 = 老人本人` 出一张六问清单或四段脚本，那就违反了 §4.2 与 §9.5。
这一类问题不降级（分析本身是有用的），只把问题回灌给模型重出一次；`查策略形态()` 是这条检查的实现。

**第 ④ 步为什么要有**：判红必须有官方出口行，且按用户 2026-10-01 的定向决定，
`12315` 与 `96110` **两个号码都要写**。提示词已经这么要求，但提示词不是契约，
出口处再加一层确定性的 `补齐官方出口()`：只补这两个官方号码，不推荐任何同类商业工具（§12）。
被兜到时记在 `日志.官方出口` 里（写给运维看，不进响应体）。

## 部署（Cloudflare Workers）

```bash
# 1. 装依赖（wrangler 没装在项目里，用 npx 即可）
cd 计划1/worker

# 2. 写入密钥：只在服务端，绝不写进代码、绝不进前端
npx wrangler secret put DEEPSEEK_API_KEY

# 3. 部署
npx wrangler deploy

# 4. 自检（把 URL 换成上一步打印出来的）
curl https://lucda-prototype.<你的账号>.workers.dev/health
```

部署完会拿到形如 `https://lucda-prototype.<你的账号>.workers.dev` 的地址。

**最后一步在 web/ 那边**（不归本目录改）：把地址填进 `web/config.js` 的 `API_BASE`，前端才连得上。

```js
// web/config.js（由 web/ 的负责人填，本目录只提供地址）
export const API_BASE = "https://lucda-prototype.<你的账号>.workers.dev";
```

### 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 无 | **必须**用 `wrangler secret put` 写；从 `env` 读，不打印、不落盘、不回显 |
| `ALLOWED_ORIGIN` | `*` | 响应头 `Access-Control-Allow-Origin`。不带凭证，所以可以留 `*` |
| `RATE_LIMIT_PER_MINUTE` | `10` | 按来源 IP、60 秒窗口的内存计数 |
| `UPSTREAM_TIMEOUT_MS` | `100000` | 上游超时 |
| `MAX_OUTPUT_TOKENS` | `32000` | 上游输出额度 |
| `THINKING_DISABLED` | 默认关 | 设 `0` 打开推理（见下） |
| `REASONING_EFFORT` | 无 | 另一个推理开关，可填 `none` |
| `MODEL_TEXT` / `MODEL_IMAGE` | `deepseek-v4-pro` / `deepseek-flash` | 换模型只改这一处 |
| `RESPONSE_FORMAT_JSON` | 默认开 | 设 `0` 关掉上游的 JSON 模式 |

## 两条实测出来的工程决定（写下来免得后人重踩）

1. **默认关掉推理。** `deepseek-v4-pro` / `deepseek-flash` 都是先出推理再出正文的模型：
   开着推理单次要 60–90 秒，而且推理会把 `max_tokens` 吃光，`finish_reason=length` 而正文为空
   （实测 `max_tokens=8000` 时推理占满 8000，`content` 是空串）。本案只要求按契约出结构化标注，
   发送 `thinking: {type: "disabled"}` 后单次 4–8 秒，判定结果不变（同一输入跑过对照）。
   需要推理时 `THINKING_DISABLED=0`。
2. **上游网络错误会重试一次。** 只对「网络错误 / 超时 / 5xx」重试（实测碰得到：一次连不上 api.deepseek.com，
   16 秒后 fetch failed，重试后正常）；4xx 是请求本身的问题，不重试。重试仍失败就返回降级对象。
3. **限流是尽力而为。** 内存计数只在同一个 isolate 内有效。跨实例严格限流要上 Durable Object 或 KV，
   本原型阶段不做（执行指令 §10.4 的 API 成本一条）。

## 本机答辩怎么用（`dev-server.mjs`）

```bash
# 密钥从环境变量读，不打印、不落盘
export DEEPSEEK_API_KEY=...
node worker/dev-server.mjs            # 默认 http://127.0.0.1:8787
PORT=8899 node worker/dev-server.mjs  # 换端口
```

启动只会打印端口、路由、限流口径，以及「已从环境变量读取」这一句，**不会打印 key 的值**。

前端把 `API_BASE` 指到 `http://127.0.0.1:8787` 即可，路由与响应格式与线上完全一致——
`dev-server.mjs` 没有另写一套逻辑，它 import 的就是 `worker.js`。

**GitHub Pages 是纯静态站，公开站着陆时默认跑离线演示模式**（`data/demo_samples.json`，
执行指令 §8.6）。现场网络不可靠，断网也要能演示；联网时再切到 Worker 出口。

## 离线演示样例

`data/demo_samples.json`：**7 条**，`红 3 / 黄 3 / 绿 1`，`文字 5 / 图片 1 / 语音 1`；
输出形态 `一句话 10 / 问题 6 / 脚本 4`，**三种形态齐备**（§11 验收 5）。
**全部由真实调用产生**，每条都留着模型原始返回、用量、耗时与禁忌扫描记录。

| 样例 | 用户 × 对抗者 | 风险 | 输出形态 | 这条是干什么的 |
| --- | --- | --- | --- | --- |
| demo-01 | 老人本人 × 推销员（面谈） | 红 | 一句话 | 红色必带官方出口（§11 验收 7） |
| demo-02 | 老人本人 × 推销员（面谈） | 黄 | 一句话 | §6.2 核心情形：「已对我生效」只来自我自己的话 |
| demo-03 | 老人本人 × 推销员（面谈） | 绿 | 一句话 | 绿色是结论 + 正常说法对照（§9.4） |
| demo-04 | 老人本人 × 广告 | 黄 | 一句话 | 图片模态：只写「没有找到」，不写「是假的」（§1.3） |
| demo-05 | 老人本人 × 推销员（面谈） | 红 | 一句话 | 语音模态：同一承诺重复 3 次 → 强度 5（§6.4） |
| demo-06 | 当事人 × 推销员（面谈） | 红 | 问题 ×6 | §9.1：6 个问题按序，每条 ≤15 字，各挂「他可能怎么答」→「你再问」 |
| demo-07 | 子女 × 亲友 | 黄 | 脚本 ×4 | §9.2：开口 / 弹药 / 反驳预判 / 给台阶，第三、四条不省 |

demo-06 与 demo-07 是 2026-10-01 补的：那之前 5 条样例的用户全是「老人本人」，
按 §4.2 就该出一句话——这是对的，但「问题」与「脚本」两种形态因此**没有被证明过**。
两条新样例的每条 `内容` 都可由 `查策略形态()` 机械核对（条数、序号、字数、段名与顺序）。

```bash
node worker/make_demo_samples.mjs          # 输入没变、且旧结果仍合当前契约的，直接复用
node worker/make_demo_samples.mjs --重跑    # 全部重跑
```

复用前会先用 `查策略形态()` 与「判红必带两个官方号码」复核旧结果：不合就重跑，
不把不合规的旧结果塞回去。单条样例最多打 3 次真实调用，3 次都不合形态就写进 `失败`，
**不手编结果去凑**。

语音样例用的是**人工转写**的时间轴文本，`说明` 里写明了这一点：不伪造 ASR 结果。

## 提示词从哪来

`worker.js` 里的 `SYSTEM_PROMPT` 是 `schema/prompt_contract.md` §1 的**逐字全文**，
由 `gen_prompt.mjs` 注入（注入会打印字数与 sha256 前 16 位，便于核对）。
system 消息里另有两段**不属于契约原文**的附录，都是为了让模型稳定出合契约的输出：

| 附录 | 内容来源 | 为什么必须加 |
| --- | --- | --- |
| `OUTPUT_SKELETON` | `prompt_contract.md` §2 与外层键表、执行指令 §6.6 | 契约讲的是「标什么」，模型还需要「键怎么写」的机械说明，否则 JSON 结构不稳 |
| `参数映射` | 执行指令 §4.2 / §4.3 / §4.5 / §8.1 / §9 / §12 与 `scenarios.md` §1.1 / §5 | 契约没把「用户 → 输出形态」「(用户,对抗者) → 路径」写成一句可执行的话；缺了它，老人档会被塞一张问题清单，违反 §4.2 与 §9.5 |
| `依据清单`（`rag_index.js`） | `data/rag_index.json`，**只取「已核实」文献** | 提示词要求「文献只能引用索引里的条目」。不把清单喂进去，模型只能把 `溯源` 留空——实测第一版就是这么被校验拦下的 |

这三段只做搬运与排版，不新增规则，也不新增契约字段。

## 已知缺口（写进交付报告的未决项）

1. **`策略.对抗者` 没有「正常商家」这一格。** 判绿的那条样例（药店的人照常说话）也必须填一个对抗者，
   模型只能填 `推销员（面谈）`。契约取值由 M1 lane 定，本目录不改契约。
2. **禁忌扫描器对「绝对化语言」这种元语言说法会误伤。** 模型写的话语层值
   「使用明确表述，未使用模糊或**绝对**化语言」含「绝对」两个字，命中绝对类规则、动作是删句，
   整条 `话语层[0].值` 就被删空，只能按 §5.5 降级把这条标签去掉（`data/demo_samples.json` 的 demo-03 里
   留着完整记录）。修法在词表侧（`data/taboos.json`）：给「绝对」加排除后缀「化」，或者改这条规则的动作。
   本目录不改 web/ 与 data/taboos.json，只能把命中与降级如实记下来。
3. **`wrangler deploy` 只跑到 `--dry-run`**：本机没有 Cloudflare 账号授权，没做过真实部署。
   `npx wrangler@4 deploy --dry-run` 通过（Total Upload 101.23 KiB / gzip 27.06 KiB；
   `DEEPSEEK_API_KEY` 不在 binding 名单里，证实它是走 secret 的）。
4. 上游是第三方接口，模型偶有措辞不稳（例如把面谈的对抗者写成「先挂了」）；契约校验拦不住这类语气问题。
5. 绿档的 `策略.输出` 出现过「要买去正规药店」：是对渠道的建议，不是对产品的背书，
   但离「不得暗示可以买」（§9.4、§12）的边界较近。锚点用的字符区间是模型给的，偶有切在半词上的情况
   （demo-03 的锚点片段就是「店的人说这个保健品不能替」）。
6. **脚本形态的「弹药」段没给具体案例。** §9.2 的三层弹药里，第①层是「同类真实案件（公开报道）」。
   语料加工未完成、又没有可引的公开来源时，模型只写了社会规范与后果那一层（demo-07 就是如此）。
   这是照着铁律 13（不臆造）走的：宁可少写一层，不编一个案子。要补案例，得先有可溯源的来源。
7. **`脚本` 形态的条目会多带一个 `序号`。** schema 允许（1–6 的整数），提示词里写的是
   「其它形态不要写 序号」，模型没完全照做。前端的排序只作用在「问题」那一组，所以不影响呈现。
