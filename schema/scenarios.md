# 场景矩阵与参数推断（执行指令 §4.5 / §4.3 / §4.4 / §8.1 / §7.6）

> **用途**：给定「用户是谁 + 对抗者是谁」，定出唯一的策略。矩阵的每一格都要能直接填进 `schema/annotation.schema.json` 的 `策略` 六栏。
> **引用**：§4.2（用户）、§4.3（对抗者）、§4.4（加工路径）、§4.5（场景矩阵）、§8.1（参数从用户说的话里推断）、§8.4（推断不出时的兜底）、§7.6（说话人信号）。
> **边界**：矩阵只决定怎么说。**不说产品真假、不给法律意见**（执行指令 §1.2、§12）。
> `依据` 列：`规格` = 规格里已有的格；`扩展` = 规格未给、为覆盖 §4.3 的其它对抗者而自建，待规格确认。

---

## 0. 参数从哪来：不让用户选

**规则**：`用户` 与 `对抗者` 都从**用户说的话里推断**，不弹选项、不让用户挑（§8.1、§2.2）。用户能做的只有一件事：把东西发进来。

```text
输入（文字 / 语音 / 图片）
   ↓ 说话人识别（§7.6）
带说话人的话语单元
   ↓ 读「用户自己说了什么」
用户、对抗者
   ↓ 查矩阵（本文档 §5）
路径、语域、输出形态、禁忌方向
```

**规格给的三条推断（§8.1 原表）**：

| 用户说了什么 | 推断 |
| --- | --- |
| 「我要怎么跟他说」 | 对抗者 = 推销员 → 出问题清单 |
| 「我爸妈不信我」 | 对抗者 = 亲友 → 出说服脚本 |
| 「我已经买了」 | 对抗者 = 自己 → 出责任外部化 + 问自己一句 |

**兜底（§8.4）**：只有在**输入是无对话轮次的单段文本或广告图，且没有出现任何对抗者线索**时，才问一次「你要跟谁说？」，并且系统先猜一个并高亮，用户只需确认或改。选项四个：广告 / 推销员 / 爸妈或亲友 / 我自己。

## 1. 变量一 · 用户（§4.2）

### 1.1 规格表（照抄 §4.2）

| 用户 | 认知负荷容忍 | 语域 | 输出形态 |
| --- | --- | --- | --- |
| 老人本人 | 极低 | 口语、短句、零术语 | 一句话 + 一个动作（可朗读） |
| 子女 | 中 | 日常语、可复述 | 脚本 + 弹药 + 反驳预判 |
| 社区工作者 / 网格员 | 中高 | 半专业、可对外引用 | 说理框架 + 案例 + 可公开讲的材料 |
| 当事人（自己交涉） | 低（现场） | 短、能直接念出口 | 问题清单 |

**契约侧的对齐**：`策略.输出[].形态` 只有三值（问题 / 脚本 / 一句话，§9 三种模式契约、§11 验收 5）。上表的四行输出形态按下面映射落进契约：

| §4.2 输出形态 | 契约 `形态` | 说明 |
| --- | --- | --- |
| 一句话 + 一个动作 | `一句话` | 两条：一句结论 + 一个动作 |
| 脚本 + 弹药 + 反驳预判 | `脚本` | 弹药三层见 §9.2 |
| 说理框架 + 案例 + 可公开讲的材料 | `脚本` | 社区工作者格，弹药里必须有可公开讲的案例 |
| 问题清单 | `问题` | 6 个，按序，每条挂「他可能怎么答」「你再问」（§9.1） |

> 注：§4.2 的「说理框架 + 案例」不是 §9 三模式里的第四种形态，本文件按上表收进 `脚本`。**这一条是自建映射，已记入交付报告的未决项。**

### 1.2 从用户说的话里推断「用户是谁」（自建判据）

规格只给了「对抗者」的推断例子（§8.1），「用户」的推断由本表补上，依据是 §4.2 的四行用户＋§8.1 的推断口径。

| 用户 | 从用户说的话里可匹配的线索 | 判定方式 | 判不准怎么办 |
| --- | --- | --- | --- |
| **老人本人** | 第一人称是**被推销的对象**：「他跟我说」「他让我买」「他说能治我的病」；且**没有**出现家属视角的第三人称 | 两条同时成立 → 老人本人 | 与「当事人」都命中时，看有没有出面交涉的意图（见下行） |
| **子女** | 出现「我爸妈」「我妈」「我爸」「我家老人」「家里长辈」；或出现「他不听我的」「我说不动他」 | 被劝对象是第三人称亲属 → 子女 | 标 `说话人置信度 = 低`，按 §8.4 问一次 |
| **社区工作者** | 出现「社区」「网格」「辖区」「老同志」；或出现对外讲述的意图：「我要给他们讲」「要做个活动」 | 说话人 = 我，且听众是群体 → 社区工作者 | 同上 |
| **当事人** | 出现自己要出面交涉的意图：「我要怎么跟他说」「我该怎么问他」「我当面问他」 | 说话人 = 我，且被劝对象就是在文本里跟我说话的那个人 → 当事人 | 与「老人本人」都命中时，**有出面交涉意图 → 当事人**；没有 → 老人本人 |

**老人本人 / 当事人 的分界**：两者都是「我在说」。区别只有一条——**我有没有要出面去跟对方交涉**。有 → 当事人（输出问题清单）；没有 → 老人本人（输出一句话 + 一个动作）。

## 2. 变量二 · 对抗者（§4.3）

### 2.1 规格表（照抄 §4.3）

| 对抗者 | 可否交涉 | 关系距离 | 真正的风险 | 策略落点 |
| --- | --- | --- | --- | --- |
| 广告 / 直播 / 包装 | 否，**无交涉对象** | — | 反复曝光后麻木 | 只做识别 + 自保，**不出问题清单** |
| 推销员（面谈） | 可 | 陌生·职业说服者 | 被话术绕回去 | 中心路径质问 |
| 推销员（电话） | 可 | 陌生·可挂断 | 对方直接挂断 | **先锁住对方**，再问 |
| 亲友 | 可 | 亲密·有感情债 | 关系受损 | 边缘路径 + 面子保全 |
| 自己（已买已投） | 可 | 零距离·沉没成本 | 面子·自我辩解 | 责任外部化 |
| 亲友即推销者 | 可 | 关系与利益叠加 | 最难，两难 | 关系优先，不质证 |
| 平台 / 客服 | 可 | 程序性 | 无凭证 | 程序化交涉（证据清单） |

**取值对齐**：契约 `策略.对抗者` 的取值按上表；§4.5 矩阵里的「父母」收进 `亲友`；「广告 / 直播 / 包装」三合一收进 `广告`。§4.5 与 §5.3 还用了一格 `老人（群体）`（用户 = 社区工作者），§4.3 的表未列，契约里单列了这个取值。

### 2.2 从用户说的话里推断「对抗者是谁」

| 对抗者 | 从用户说的话里可匹配的线索 | 来源 |
| --- | --- | --- |
| **推销员（面谈）** | 「我要怎么跟他说」；出现「来家里」「上门」「在店里」「到楼下」；出现第二人称祈使的转述 | 规格 §8.1 ＋ 扩展 |
| **推销员（电话）** | 「打电话」「电话里」「天天给我打电话」「陌生号码」 | 扩展（§4.3 标为「陌生·可挂断」） |
| **亲友** | 「我爸妈不信我」；被劝的人跟我有亲属或朋友关系，且**不是卖东西的一方** | 规格 §8.1 |
| **亲友即推销者** | 被劝的人跟我有亲属或朋友关系，**且是卖东西的一方**：「我侄子卖这个」「我小姨让我买她代理的」 | 扩展（§4.3 标为「关系与利益叠加」） |
| **自己** | 「我已经买了」「我已经投了」「我不甘心」 | 规格 §8.1 |
| **广告** | 输入是**无对话轮次的单段文本或广告图**，没有出现任何跟我对话的人 | 规格 §8.4 |
| **平台客服** | 「客服说」「平台让我」「官方客服」「工单」 | 扩展（§4.3 标为「程序性」） |
| **老人群体** | 用户已被推断为社区工作者，话语里提到要面对的听众是老人群体 | 扩展（§4.5、§5.3 的该格） |

## 3. 说话人信号（§7.6）在推断里的用法

推断 `用户` 与 `对抗者` 的前提，是先分清哪句话是谁说的。

| 信号 | 指向 | 可靠度 | 用在推断的哪一步 |
| --- | --- | --- | --- |
| 第二人称（「您」「阿姨」）+ 祈使 | 推销者在说 | 高 | 证明「有一个推销者在对我说话」→ 对抗者不是广告 |
| 第一人称情感表述（「我很信任」「我喜欢」） | 我在说 | 高 | 证明说话人是我 → 用户不是第三人 |
| 转述标记（「小李说」「他说」「人家讲」） | 我在转述他的话 | 高 | 被转述的内容归属原说话人（`归属` 判 正在施放） |
| 拟亲属自称（「干女儿」「家人」） | 推销者在说 | 中 | 辅助判「亲友即推销者」还是「推销员（面谈）」 |

**三道保险与低置信度处理见 `schema/prompt_contract.md`**（§7.6：人称与转述标记 → 置信度门槛 → 冗余判定）。置信度低时不得静默通过，必须显著提示 + 一键纠正（§11 验收 13）。

## 4. 加工路径匹配规则（§4.4）

说服研究里的经典模型：**中心路径**（讲理据，需要对方有动机、有能力加工）与**边缘路径**（靠情感、紧迫、从众、人际线索）。

**推销者的战术本质：对老人全用边缘路径。** 「院士研发」「最后三盒」「都在买」，从不讲证据。

| 对抗者 | 必须走的路径 | 理由（§4.4 原表） |
| --- | --- | --- |
| 推销员 | 中心 | 他是职业说服者。对专业人士喊口号＝输 |
| 亲友 | 边缘 + 社会规范 | 讲理据越硬越反弹（「你懂什么」） |
| 老人自己 | 边缘·极简 | 对老人讲科学必败——这正是推销者会赢的地方 |
| 亲友即推销者 | 边缘（关系优先） | 质证会毁关系，对方还会打感情牌 |
| 广告 | 边缘 | 无交涉对象，只做识别 + 自保 |
| 平台客服 | 中心 | 程序性交涉，按清单推进（扩展） |

> **说服失败的头号原因，是对着该走边缘路径的人讲中心路径。**

**冲突时的裁决**：路径由 `(用户, 对抗者)` **共同**决定，以 §5 矩阵的格为准；矩阵没覆盖的组合，按本节的对抗者表。所以同一个「推销员」，用户是老人时走边缘、用户是当事人或子女时走中心——**同一对抗者，用户不同，输出完全不同，固定三模式不够。**

## 5. 场景矩阵（§4.5）

每格给出：用户 / 对抗者 / 路径 / 输出形态 / 禁忌方向。`语域` 由第 1 节的用户表决定（见 §7）。

| # | 用户 | 对抗者 | 路径 | 输出形态（可直接念出口） | 禁忌方向 | 依据 |
| :--: | --- | --- | --- | --- | --- | --- |
| 1 | 老人本人 | 推销员（面谈） | 边缘 | 一句话 + 一个动作：「他让你现在掏钱。先回家。」 | 不说「你被骗了」 | 规格 §4.5 |
| 2 | 老人本人 | 广告 | 边缘 | 一句话：「这是广告，别信。」 | 不给问题清单 | 规格 §4.5 |
| 3 | 老人本人 | 自己 | 边缘 | 一句话 + 问自己一句：「专门骗人的，谁都躲不过。」＋「如果他不卖东西，还会这样对我吗？」 | 不否定其判断力 | 规格 §4.5 |
| 4 | 子女 | 亲友 | 边缘 | 脚本：4 段 ＋ 弹药 ＋ 反驳预判 | 不说「我跟你说过多少次」 | 规格 §4.5（对抗者原写作「父母」） |
| 5 | 子女 | 推销员（面谈） | 中心 | 问题清单（质问） | 不喊「骗子」 | 规格 §4.5 |
| 6 | 社区工作者 | 老人群体 | 边缘 + 社会规范 | 脚本：可公开讲的案例 ＋ 一句口诀 | 不点名羞辱当事人 | 规格 §4.5 |
| 7 | 当事人 | 推销员（面谈） | 中心 | 问题清单：6 个，按序问 | 不威胁、不激化 | 规格 §4.5 |
| 8 | 老人本人 | 推销员（电话） | 边缘 | 一句话：「不认识的人让你掏钱。先挂了。」 | 不在电话里争辩 | 扩展 |
| 9 | 子女 | 推销员（电话） | 中心 | 问题清单：先锁住对方，再问 | 不喊「骗子」 | 扩展（§9.1 电话变体） |
| 10 | 当事人 | 推销员（电话） | 中心 | 问题清单：先锁住对方 ——「您先别挂，我就问三个」 | 不威胁 | 扩展（§9.1 电话变体） |
| 11 | 子女 | 亲友即推销者 | 边缘 | 脚本：关系优先变体，不质证 | 不质问、不指控 | 扩展（§4.3、§9.1） |
| 12 | 老人本人 | 亲友即推销者 | 边缘 | 一句话：关系优先，先不表态 | 不质证 | 扩展（§4.3） |
| 13 | 子女 | 平台客服 | 中心 | 问题清单：程序化交涉，按清单要凭证 | 不指控对方违法 | 扩展（§4.3） |
| 14 | 当事人 | 平台客服 | 中心 | 问题清单：程序化交涉，按清单要凭证 | 不指控对方违法 | 扩展（§4.3） |

**未覆盖的组合**：`老人本人 × 平台客服`、`社区工作者 × 除老人群体外的任何对抗者` 等组合，规格未给落点。落到这些组合时**不要临时编格**，按 §8.4 的兜底问一次，并把缺口写进交付报告的未决项。

## 6. 两格特殊处理（硬约束，违反即失败）

### 6.1 广告 / 直播 / 包装

```text
无交涉对象
   → 只做「识别 + 自保」
   → 绝不出问题清单
```

| 项 | 要求 |
| --- | --- |
| 为什么不 | 说了也没用，还会把「质问句」教给一个没人可问的人（§5.2 堵死退路、§5.3） |
| 输出形态 | 只有一句话（自保），可附正常说法对照 |
| 契约侧 | `策略.对抗者 = "广告"` 时，`策略.输出[].形态` 不得为 `问题`；已写进 `annotation.schema.json` 校验 |
| 禁忌方向 | 任何质问句 |

### 6.2 亲友即推销者

```text
关系与利益叠加，两难
   → A 对质不适用，归入 B 帮劝变体
   → 关系优先，不质证
```

| 项 | 要求 |
| --- | --- |
| 为什么不 | 一旦质证，对方必然打感情牌，关系先坏，事也谈不成（§4.4、§9.1） |
| 输出形态 | 脚本（帮劝变体）；禁忌栏必须写清「不能质问」这一条 |
| 契约侧 | `策略.对抗者 = "亲友即推销者"` 时，`策略.输出[].形态` 不得为 `问题`；已写进 `annotation.schema.json` 校验 |
| 与「亲友」的区别 | 亲属或朋友**在卖东西** → 亲友即推销者；亲属或朋友**只是被劝的人** → 亲友 |

## 7. 每一格怎么填满 6 栏（§4.1、§11 验收 6）

| 栏 | 取值来自 | 本矩阵的位置 |
| :--: | --- | --- |
| ① 用户 | §1.2 推断 | 本文件第 5 节的「用户」列 |
| ② 对抗者 | §2.2 推断 | 第 5 节的「对抗者」列 |
| ③ 路径 | §4.4 ＋ 本矩阵 | 第 5 节的「路径」列 |
| ④ 语域 | §4.2（由用户决定） | 第 1.1 节用户表的「语域」列 |
| ⑤ 输出 | §4.2 ＋ §9 | 第 5 节的「输出形态」列 |
| ⑥ 禁忌 | §5.3 组合禁忌 ＋ 本矩阵的「禁忌方向」列 | 第 5 节的「禁忌方向」列 |

**硬规则**：任一条说服输出缺第 ⑥ 栏即为不合格（§4.1）。契约里 `策略.禁忌` 是 required 且不得为空数组。

**禁忌扫描在送出前执行，不是写作时执行**（§5.5）：输出 → 扫 §5.3 对应格 → 扫 §5.4 词表 → 命中就重写再扫 → 放行。词表与 10 条预置用例见 `schema/taboos.md`。
